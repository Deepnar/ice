# ICE Post-Paper Roadmap

> Living checklist of everything queued after the paper. Distilled from [rough_post_paper_work.md](rough_post_paper_work.md) (raw notes — keep that file as the source of nuance), the experiment reports in `experiments/*/results*`, and the paper's limitations section.
>
> **How to use this file:**
> - **Work it in order** (Phase 0 → Track A → B → …), respecting dependencies. The ordering is deliberate.
> - **Build up, never replace.** Each item must be implemented so that *later* items build on top of it, not tear it out. Concrete example: the decay / background-worker scheduling fixes (C7) are later absorbed by the agentic Memory Maintenance Agent (Track D) — so do C7 with clean, composable worker interfaces the agent can later orchestrate, not a throwaway patch. When implementing any item, check what downstream items depend on it and design for that end-state.
> - Each entry is *intent + rationale*, **not a spec**. When an item's turn comes, the concrete design gets discussed in-session first; only then is it implemented.
> - Check off `[x]` when done. On completion, update [ICE_Architecture.md](ICE_Architecture.md): new systems get a new section, reworked systems get their existing section edited.
> - Phase 0 decisions may kill, reshape, or re-home items below (some conversational features may move to the Coding side). That is expected.
>
> > **Corrections (verified in code, 2026-07) — the paper's limitations section repeats two claims that are false in the actual code; fix before arXiv:**
> 1. **NER was loaded, not regex-fallback.** [ner_utils.py](../src/retrieval/ner_utils.py) loads `models/ner/ner_model.pt` (present on disk) and only regex-falls-back if that file is missing. NER was active during the experiments (empirically ~95% recall). Codex's weak numbers come from other handicaps, **not** entity detection.
> 2. **No "corroboration trap" starving retrieval.** Codex retrieval filters only on `valid_until == None` (time-validity) in `_traverse_graph`, MERA, and context_payload regeneration — **none filter `confidence == 'active'`**. So `pending` (single-extraction) edges *are* traversed and injected; `confidence=='active'` only gated a coarse 1.5× score boost. The claim that pending edges never contribute to retrieval is false. The real Codex weaknesses are chunk size (A1), entity-vs-relation retrieval (A4), leg under-representation (A10), and an inert confidence signal with no reinforcement (A3, now fixed).

## Track A — Codex overhaul (highest-leverage rework)

The experiments showed Codex is the most ambitious *and* most handicapped subsystem. These items are ordered so each builds on the last. **North star:** the end state is a *real* knowledge graph — rich per-entity payloads, community/topic summaries, relation-aware answering — not "a list of entities with arrows." A1–A6 make the base pipeline trustworthy and dense; A7–A8 make it a genuinely functional graph. Do the earlier items in a way that A7's unified/code-aware graph slots on top rather than replacing them.

- [x] **A1 Extraction chunking fix** `(rework)` — Done 2026-07. New `_chunk_text` in [codex_extractor.py](../src/workers/codex_extractor.py) does sentence-aware (prose) + code-line-aware (fenced code) chunking, greedy-packed to `CHUNK_TOKENS`=550 with `OVERLAP_WORDS`=50; code counted at heavier token density; short turns pass through as one chunk. Chunk size is shared with A2's NER pass. Mechanics validated with a standalone test (chunk sizes bounded, sentences/code lines intact, overlap present). **Pending end-quality validation** (needs GPU services + populated DB): re-extract a sample via `experiments/mature/diagnose_codex.py` / `tests/test_codex_extractor.py` and compare entity-drop + `X uses X` hallucination rate before/after.
- [x] **A2 NER-grounded extraction (hybrid CPU/GPU pipeline)** `(rework)` — Done 2026-07. Per A1 chunk, [codex_extractor.py](../src/workers/codex_extractor.py) runs the shared CPU micro-NER (`extract_entities`), injects a CONFIRMED ENTITIES block into the extraction prompt, and post-filters via `_ground_triplets`: a triplet's subject (and, for non-property relations, object) must match a confirmed entity by normalised-exact or token-subset comparison, else it's dropped. Property relations ground subject only (object is a value). Added a self-reference filter (`subject==object`) that kills `fastapi uses fastapi`. Empty-NER chunks skip grounding (no anchor). Logic validated by standalone test. **A3 seam:** `_ground_triplets` returns `(grounded, rejected)` — A3 flips the call site from drop→keep-low-confidence (one line). **NER quality was checked empirically first** (see A9): ~95% recall but with subword truncation, boundary bleed, and pronoun false-positives. Fixed the grounding-critical ones in `ner_utils` (word-boundary snapping, function-word edge-trim, junk filter, dedup) — truncation was the only flaw that broke grounding; the rest are token-subset-absorbed. **Pending live validation:** the `codex_grounding` log lines give the over-rejection rate; **retrain NER only if that rate shows systematic under-coverage** (answer from data, not upfront).
- [x] **A3 Edge confidence/strength as a live retrieval signal** `(rework)` — Done 2026-07. **Corroboration-trap correction:** the premise that "pending edges are never retrieved" is *false in code* (second paper-vs-code myth after NER — see correction block). Retrieval (`_traverse_graph`, MERA, context_payload) filters only on `valid_until == None`, so pending edges *are* traversed; `confidence=='active'` only gated a coarse 1.5× fragment boost. The real problem was that strength/confidence was an almost-inert signal with no reinforcement loop and unconditional depth-3 traversal. Shipped in [orchestrator.py](../src/retrieval/orchestrator.py): (1) **strength-gated traversal** — deep hops require `strength ≥ CODEX_DEEP_STRENGTH_FLOOR`; matched-entity direct edges always expand (cuts depth-3 pollution); (2) **retrieval-reinforcement** — `_reinforce_codex_edges` boosts the matched-entity *anchor* edges' strength on retrieval (episodic `decay_score`+=0.15 analog; anchor-only to avoid diluting the neighborhood; write-on-read); (3) **graded fragment score** (1.0–1.5 from mean matched-edge strength) replacing the binary 1.5×. **No schema migration** — used existing `strength`; a distinct `extraction_confidence` column was dropped as premature (A6/A7 will define confidence with real purpose). **Pending live validation** (needs DB + codex): confirm reinforcement/decay balance and traversal-pollution reduction. Note: full per-edge granularity depends on A10 (multi-fragment representation).
- [ ] **A4 Relation-aware retrieval + NER/relations retrain** `(rework)` — Search by relation as well as entity ("who inspired X", "name"-relation queries), boosting where relation hits and entity hits overlap. Closes the semantic-vs-lexical gap: today "main fortress" never resolves to "The Obsidian Citadel" — not because NER fails to tag it, but because Codex retrieval is entity-centric (exact canonical/alias + 0.85 vector fuzzy match over context_payload) and assumes users name entities canonically. Relation-aware traversal + better query→entity resolution is the fix. **Also absorbs two Phase-0 items:** (a) re-home MERA's category/enumeration answering here (P0.2) so the primary leg handles "list all X" queries; (b) add **grounded query expansion** (expand via NER entities + Codex neighbours, no LLM answer-fabrication) as the sane replacement for the mislabeled HyDE code.
- [ ] **A5 Codex conversation-scoping division** `(bug)` — Massive technical conversations (ice_dev) pollute the shared graph; extraction/retrieval need per-conversation/project scoping inside Codex.
- [ ] **A6 Self-correcting graph (reconciliation loop)** `(new)` — Before saving, `check_conflict()` against existing edges; on conflict, re-prompt the extractor to reconcile (merge/expire/update) instead of blind-saving. Turns the extractor from passive triplet collector into an active state reconciler. (Pairs with Track D tooling.)
- [ ] **A7 Codex V3 — one unified, code-aware graph** `(new)` — Add a deterministic static-analysis layer: AST-level entities (deterministic IDs from definition sites), deterministic edges (`imports`, `calls`, `inherits`, `defined_in`, `tested_by`), and Graph-RAG-style community summarisation (Louvain/Leiden over the import/call graph, LLM summary per community). **Constraint from the notes: there is ONE Codex** serving both conversation and coding modes — not two graphs. OKF is adapted here as design philosophy (typed knowledge units in our tables, not markdown files).
- [ ] **A8 Expand codex relations** `(new/open)` — The current set arent that diverse, for example there is not negetive version of exisiting relations so the ai chooses the positive instead, also we cant just make it wayy bigger as that also counts into what is being sent to the model. *(Confirmed from the vocab: `friend/enemy` and `married_to/is_divorced_from` have negatives, but most relations are positive-only — `uses` has no "stopped_using/deprecated", `trusts` no "distrusts", `works_with` no "conflicts_with", and there are no temporal "former_X" forms. When a fact is negative/absent the extractor skips it or grabs the positive → a false edge. valid_until expiry partly covers "no longer true" but not asserted-negative facts. The token-budget tension is real: the whole vocab is rendered into every extraction prompt. This is the relation-side analog of A2's entity grounding — likely wants a small set of high-value negatives + a "negated"/polarity flag on edges rather than doubling the vocabulary.)*
- [ ] **A9 Context-aware NER rework** `(new/open)` — The micro-NER is context-free: each subword token is embedded in isolation and classified by an MLP, so it can't use surrounding words. Empirically ~95% recall but with verb-led boundary bleed (`uses PostgreSQL`) and descriptor false-positives (`fire mage`, `very sad`, pronouns). The cheap post-processing fixes shipped with A2 (word-boundary snapping, function-word edge-trim, junk filter) handle the grounding-critical cases, but the root fix is a context-aware tagger — embed tokens **in context** (per-token hidden states over the whole sentence) or a proper token-classification head, then retrain. Do this only if A2's live over-rejection logs or retrieval quality show NER is the bottleneck; recall is already good, so this is precision/boundary polish, not urgent.
- [ ] **A10 Codex leg representation + budget fairness** `(new)` — The codex leg collapses its entire traversal into **one** concatenated `ContextFragment` ([orchestrator.py](../src/retrieval/orchestrator.py) `_codex_graph`), so in `_enforce_token_budget` it can occupy at most one slot no matter how relevant, while episodic emits dozens of fragments and soaks the greedy fill — a structural reason codex was only 3.3% of fragments (not just extraction weakness). Fix: (a) return **multiple scored fragments** (per entity/subgraph) so each competes in fusion/budget on its own relevance and irrelevant depth-3 entities drop out instead of bloating one blob; (b) **budget-fill fairness** — per-leg floor/quota in `_enforce_token_budget` so episodic stops dominating the remainder (affects procedural too). This is the companion to A4 (relation-aware retrieval naturally yields per-relation fragments) and where A3's per-edge strength becomes per-fragment score. Confirmed via code audit 2026-07; raised by user (episodic-preference intuition — correct).

## Track B — Classifier & routing

- [ ] **B1 Classifier retrain: multi-label context-reliance + cloud toggle** `(rework)` — Real_Time_Search is orthogonal (a Zero_Shot or LTM prompt can *also* need real-time), so context-reliance shouldn't be single-label 3-way. Add a toggleable "cloud" routing signal for users with API models. The Coding side may need new intent labels too.
- [ ] **B2 Replace the hard LTM override with a principled combination** `(rework)` — The >10-turns / low-confidence ⇒ LTM override is a loose fix that masks the classifier (system is "safe, not smart"). Treat classifier confidence as a prior combined with a conversation-length prior (Bayesian-ish) instead of a hard threshold.
- [ ] **B3 Learned MoE routing** `(rework)` — Current router is a hardcoded overlap scorer; empirically neutral-to-harmful (≈−0.02 Exp2, −0.04 Exp1) and blind to confidence and context-reliance. Wanted: confidence-weighted routing, Zero_Shot→small-model / LTM→big-model policies, a lightweight bandit over empirical per-topic performance, and model-load integration (preload/keep-warm to kill the 5–15 s Ollama swap spike). LSREP replays can train the policy offline.
- [ ] **B4 Feedback loop + fine-tune promotion (close the broken loop)** `(bug/planned)` — Thumbs-up/down per response: up ⇒ auto-add to curated set; at ~100 downs, offer to auto-label with a strong model, then user reviews via toggle-button UI; feature OFF by default for inexperienced users. Critically, fix promotion: today `fine_tune.py` loads hardcoded `v2_final.pt`, writes `finetuned_{ts}.pt`, and the live path is `v3_qwen_ft3.pt` — the weekly fine-tune changes nothing. Auto-promote the new checkpoint to `settings.classifier_model_path` (with restart/reload).
- [ ] **B5 Ensemble classifiers** `(open — parked)` — Soft-voting over 2–3 heterogeneous classifiers. Explicitly an *extreme-scenario-only* option if retraining can't hit accuracy targets.

## Track C — Retrieval & memory quality

- [ ] **C1 Lossless / inject_raw rework + better summarisation** `(rework)` — Currently effectively everything lossless injects raw; need a real dynamic decider between raw vs summary, and higher-quality summaries.
- [ ] **C2 Big-input handling** `(rework)` — Massive pasted inputs currently go in whole (is_document bypasses the word cap). Chop at ingestion; inject only relevant chunks, never the entire doc.
- [ ] **C3 Extreme-density retrieval (ICE-Dev follow-up)** `(new)` — Chunk-aware retrieval (retrieve chunks, not turns), hierarchical summaries (abstract → medium → full), section-level document decomposition, smarter truncation. Why: the vector baseline collapsed to 94.2% failure on ICE-Dev because giant turns blew the context window; ICE won there (4.33 vs 1.23) but the same failure class threatens ICE at higher density.
- [ ] **C4 Whole-conversation batch summary** `(planned)` — A conversation-level summary object so a model answering in isolation still gets global conversation info — prerequisite if the sliding window is ever removed/shrunk.
- [ ] **C5 Clustering fix** `(bug)` — Exp2 showed over-merging (2–3 mega-clusters + dozens of singletons, sometimes one giant cluster) and top-30→top-10 cluster scoping that defeats the purpose. Fix merge thresholds, cluster count, and name/description quality (needed for cross-chat UX in C6).
- [ ] **C6 Session IDs + scoping semantics rework** `(rework)` — Introduce a session_id per sitting (turns in one session are likely same-topic ⇒ better clustering; also the hook for decay catch-up, C7). Rethink scopes: `none` should behave like true incognito; `manual` becomes a mode *inside* auto/project rather than a peer; user can toggle extra conversations into scope from the sidebar (cross-chat retrieval over N ticked convos) and `@`-mention a specific conversation/turn for one-off context.
- [ ] **C7 Decay/worker scheduling rework** `(bug/open)` — All decay depends on the app staying open; a user who closes it gets no maintenance. Run catch-up at session start based on gap since last session (msgs + elapsed time + calendar spread of mini-sessions). Decay is cheap enough for session-start; **open question:** where to put fine-tuning, which is expensive even on strong hardware.
- [ ] **C8 Time-weighted episodic retrieval** `(planned — F9)` — Architecture specifies time-weighted cosine; implement the recency weight in the vector score itself.
- [ ] **C9 Procedural memory + slots rework** `(rework)` — Procedural is gated to 3 intents and contributed ~nothing (+0.02); widen/rethink so people actually feel it. Slots: split into global slots vs per-conversation slots; allow agentic slot updates from chat (ties to D1/C11). (Also noted: the probes may simply not have exercised procedural — an eval problem, but the feature still needs to earn its place.)
- [ ] **C10 Deletion feature** `(planned)` — Conversation deletion with correct cascade semantics: episodic rows deleted; Codex edges solely supported by that convo demoted/expired (corroborated ones stay); procedural `source_batch_ids` pruned (deactivate if orphaned); batch summaries + session replays deleted.
- [ ] **C11 User memory control through chat** `(planned)` — "add X to pending items", "search specifically for Y" — chat-level commands that write slots / steer retrieval directly.
- [ ] **C12 RAG leg completion** `(planned)` — Proper document pipeline (PDF, CSV, …), per-conversation uploads, and a sidebar way to add an existing document into another conversation's scope.
- [ ] **C13 Caching strategy** `(open)` — Never designed at all. Decide what to cache (embeddings, cluster scores, classifier outputs, hot fragments) and whether Redis or in-process.
- [ ] **C14 KV-cache persistence & cache-aware retrieval** `(open — long-term)` — Stable-prefix ordering is right but empirically only ~10–15% of the prompt is cacheable today. Investigate persistent prefix KV storage, cache-aware fragment selection, incremental prefix updates — depends on backend (Ollama/vLLM/SGLang) cache APIs.
- [ ] **C15 Wide-net fallback budget** `(bug)` — The 2,000-token hardcoded ceiling ignores conversation length/available budget; make it dynamic.

## Track D — Active ICE (agentic background maintenance)

- [ ] **D1 Memory Maintenance Agent** `(new)` — Replace the fixed extract→save pipeline with a small tool-using agent (3B/4B, guided decoding) running in idle GPU time. - [ ] **D3 Agentic telemetry** `(new)` — Expose the agent's decisions/reasoning through SSE so its actions are visible (feeds Track F telemetry).

## Track E — Coding Mode / Project State Engine

The second operational profile: same frontend, proxy, classifier, registry, and worker infra; different stores and pipeline. Gated by `memory_scope_type == "coding"` on the conversation.

- [ ] **E1 Project State Engine schema** `(new)` — Tables: `project_state` (goal, branch, last task/session), `architecture_clusters` (feature-based file groupings), `decisions` (temporal versioning à la codex_edges), `tasks` (with commit hashes + files_changed), `development_patterns`, `daily_checklist`. Design against Codex V3 (A7) so code knowledge lands in the *one* unified graph — the rough notes explicitly say to rethink these tables in cohesion with the revamped Codex/OKF philosophy, not to blindly build them as drafted.
